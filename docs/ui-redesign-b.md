# Web UI 刷新仕様 — B案「iOS 時計アプリ型」

デザインキャンバス（B案の 2 枚が正）: https://claude.ai/artifact/6mwXm3qJ1q4tFrN4x9aMEB
（「B · 予定一覧（時計アプリ風）」「B · 予定を追加」。A案・C案は参考のみ）

## 前提

- **主な利用環境は iPhone の Safari**（LAN 内から開く／ホーム画面に追加）。PC は補助。
  390px 幅を基準に設計し、PC ではその幅のまま中央寄せ（最大 560px 程度）でよい。
- 今の方針は変えない: **ビルド工程なし・依存ライブラリなし**（`web/index.html` / `style.css` / `app.js` の素の HTML/CSS/JS）。
  外部 CDN は使わない（この Mac の中だけで完結させる方針のため）。書体は **M PLUS Rounded 1c** を
  `web/fonts/` に同梱して sounder 自身が配信する（Google Fonts などの外部には取りに行かない）。
  ウェイトは Light(300) / Regular(400) / Medium(500) / Bold(700) の 4 つを woff2 で同梱し、CSS もこの 4 つに揃える。
  予定名は自由入力なのでサブセットはしない（1 ファイル約 1MB。`/fonts/` だけ長期キャッシュさせる）。
  ライセンスは SIL Open Font License 1.1（`web/fonts/OFL.txt`）。
  読み込み前・失敗時の代替は `-apple-system, BlinkMacSystemFont, "Hiragino Sans", sans-serif`。
- 既存 REST API はそのまま使う。タイムラインは週カレンダー用の `GET /api/calendar` を使い、
  過ぎた予定の結果（`result`）と全体スイッチの状態（`master_enabled`）を足して対応する（後述）。
  ほかは静的配信で同梱フォントの Content-Type と `/fonts/` の長期キャッシュを返す程度。
  合言葉の入力画面もこの書体で出すため、`/fonts/` とアイコン・manifest だけは合言葉なしで配る。
- 既存機能は一つも落とさない（予定の CRUD・有効切替・複製・試聴・予告の試聴・よく使う型・
  毎週／毎月（日付・月末）／毎年／1回だけ／一定間隔の繰り返し・過去の日時の警告・
  サウンドのアップロード/削除/試聴・設定・禁止時間・全体オン/オフ・順番待ちを含む停止・ログ・
  ハッシュでの画面切り替え（戻る操作）・`n` キー）。
- 純粋関数（日付・表示文字列・禁止時間の判定など）は `web/lib.js` に置き、`tests/web_lib_test.js` で検証する。

## iOS 対応（必須）

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
- `apple-mobile-web-app-capable` / `apple-mobile-web-app-status-bar-style` / `apple-mobile-web-app-title=sounder`、
  `apple-touch-icon`（`web/icon-180.png`。`sounder/icon.py` で生成）、`manifest.webmanifest`、`theme-color`（ライト/ダーク）。
- 上下とも `env(safe-area-inset-*)` を考慮（下タブバーはホームインジケータ分の余白を含める）。
- 入力欄は font-size 16px 以上（iOS のズーム防止）。
- `-webkit-tap-highlight-color: transparent` と、押下時の `:active` 表現を用意。
- 画面全体の横スクロールを出さない。`overscroll-behavior` で背面のスクロール連鎖を防ぐ（シート表示中）。

## 画面構成

下タブバー（固定・半透明 `backdrop-filter: blur`）: **予定 / タイムライン / サウンド / 設定**。
現在の上部固定バー（時計・全体スイッチ・停止）は廃止し、下記に再配置する。

タブはハッシュで切り替える（`#timeline` / `#sounds` / `#settings`、予定は空）。ブラウザの戻る操作で
前のタブに戻り、ブックマークもできる。以前の画面のハッシュ（`#list` / `#week`）は予定／タイムラインとして開く。
Mac などの広い画面でも、中央寄せの 1 カラム（最大 560px）のまま使う。

### 1. 予定（ホーム）— キャンバス「B · 予定一覧」

- ナビ行: 左「編集」（テキストボタン）、右「＋」（新規）。
- 大見出し「予定」（34px / bold）。スクロールすると小さい中央タイトルに縮む（iOS の large title 風。できれば）。
- **次の予定バナー**（白いセル）: ベルのアイコンタイル ＋「次は あと13分 · 今日 8:05」「お出かけの時間（10分前の予告）」＋ 右に試聴（▶）と停止（■）の 44px 円ボタン。
  - 再生中（`/api/now` の `playing`）は停止ボタンをアクセント色で強調。停止は順番待ちの音もまとめて取り消す。
  - **全体オフのとき**はこのバナーを「全体がオフです — 予定は鳴りません」＋「オンにする」ボタンに差し替える（見落とし防止）。
  - 次の予定が**禁止時間**に当たる（`next_events` の `quiet`）ときは、タイルを月のアイコンにして名前を取り消し線にし、
    「禁止時間（23:00〜7:00）なので鳴りません」と赤字で添える。
  - いま禁止時間の中なら小さく「いまは禁止時間です（23:00〜7:00）」と添える。
- 予定リストはグループ（見出し＋角丸セル群）で 5 区分: **毎週**（weekly）／**毎月**（monthly）／**毎年**（yearly）／
  **一定間隔**（interval）／**1回だけ**（once）。空の区分は出さない。区分内は日付・時刻順（毎月末は月内の最後）。
- 行の構成（時計アプリのアラーム行）:
  - 1 行目: 大きな細字の時刻（毎週・毎月・毎年は 44px weight 300、interval の「9:00 – 21:00」や once の「9/27（日）6:30」は 30px）
  - 2 行目: 「名前 · 繰り返しの要約」（例: お出かけの時間 · 平日 ／ 支払い日 · 毎月末 ／ 記念日 · 毎年1月1日）
  - 3 行目（補助色 12px）: 鳴らすもの＋予告（例: ピンポーン＋読み上げ · 10分前・5分前に予告）
  - 鳴らない理由があれば 4 行目に赤字で出す: 「禁止時間なので鳴りません」（本番がすべて禁止時間）／
    「禁止時間にかかる回は鳴りません」（一定間隔の一部）／「日時が過ぎています」（過去の 1回だけ）
  - 右端に iOS 風スイッチ（51×31）。OFF の行は文字を `--ink-off` に。
  - **行タップで編集シートを開く**。
- 「編集」モード: 各行の左に赤い削除（−）ボタン、右に「複製」。「完了」で戻る。左スワイプで削除は任意（余裕があれば）。
- 予定が 0 件: イラストなしのシンプルな空状態＋「よく使う型から作る」の一覧と「白紙から作る」。
- `n` キーで新規（PC 用、現状維持）。

### 2. 予定の編集シート — キャンバス「B · 予定を追加」

- 下からせり上がる全画面シート（`<dialog>` を流用可）。ナビ: 左「キャンセル」、中央「予定を追加 / 予定を編集」、右「保存」（bold アクセント）。
- 最上部に**時刻**。キャンバスはホイール表示だが、実装は `<input type="time">` を大きな表示（56px 程度、細字）で見せ、タップで iOS ネイティブのホイールを出す形で良い。
  - kind=once のときは日付も同様に大きく。kind=interval のときは「開始〜終了」を表示。
  - その下に、サーバの `describe()` と同じ言い方の要約（例: 毎月末 10:00（10分前に予告））を小さく出す。
  - 「1回だけ」で過去の日時を選んだら「この日時はもう過ぎています。保存しても鳴りません。」と帯で知らせる。
- グループ 1（見出しなし）: **繰り返し ›**（値: 平日 / 毎日 / 火・金 / 毎月25日 / 毎月末 / 毎年1月1日 / 1回だけ 9/27（日） / 60分ごと）、**名前**（インライン入力）。
- グループ「鳴らすもの」: **サウンド ›**（値: ピンポーン）、**読み上げ ›**（値: 文章 or オフ）、音量スライダー行（左スピーカーアイコン、右に試聴ボタン）、繰り返し回数（×1〜10、ステッパー）。
- グループ「事前の予告」: **予告 ›**（値: 10分前・5分前 / なし）、「あと○分です」と読み上げ（スイッチ）、予告のサウンド ›（予告があるときだけ）、予告を試聴。
- メモ（任意）の入力行。
- 編集時のみ末尾に「この予定を複製」「この予定を削除」（赤）ボタン。複製は編集中の内容（保存前の変更も含む）を
  「○○ のコピー」という新しい予定として開き直す（まだ保存しない）。
- 「›」行はシート内で**右からプッシュする子画面**（左上「‹ 戻る」）:
  - 繰り返し: セグメント（毎週 / 毎月 / 毎年 / 1回 / 間隔）→
    毎週: 月〜日のチェック行＋「平日 / 週末 / 毎日」のクイック選択。
    毎月: 日（1〜31日と「月末（28〜31日）」の選択）。29〜31日を選んだら「その日が無い月は鳴りません。毎月必ず鳴らしたいときは『月末』を」と注意。
    毎年: 月と日（日は毎月と同じ選択肢）。
    1回だけ: 日付。一定間隔: 間隔（5分〜12時間の選択）・開始・終了・曜日。
  - サウンド: 内蔵 / 自分のファイル / システム の区分リスト。行タップで選択（チェックマーク）＋その場で試聴。
  - 読み上げ: オン/オフ、文章（textarea）、声（リスト）、速さスライダー。
  - 予告: 1/3/5/10/15/20/30/45/60/90/120分前 のチェック行（複数、最大 8）。
- 新規作成時はシート最上部に「よく使う型」（お出かけ・朝のメロディー・時報・休憩・ゴミ出し・毎月の支払い・記念日・おやすみ）を
  横スクロールのカードで出し、タップで値を流し込む。
- エラーはシート上部に赤文字で表示（現状どおりサーバのメッセージ）。

### 3. タイムライン（新規タブ）

C案「今日のタイムライン」を B の見た目で実装する。
- 上部: 週の曜日帯（月〜日、今日を黒丸で強調、予定のある日に小さな点）。左右スワイプまたは ‹ › で前後の週（PC は ← → キーでも）。
  「＋」で選んでいる日に「1回だけ」の予定を作る。
- 本体: 選んだ日の 0:00〜24:00 を縦の時間軸で表示（1 時間 ≈ 64〜104px）。表示時に現在時刻付近へ自動スクロール。
  - 現在時刻の線（アクセント色＋時刻ピル）。1 分ごとに位置更新。
  - 本番の予定はカード（時刻・名前・鳴らすもの・「あと○分」）。予告は本番カードに「8:05 予告」「8:10 予告」のピルでまとめ、軸上に小さな白抜きの点も打つ。
  - 一定間隔の予定（時報など）は小さなピル（「9:00 時報」）で詰めて表示。
  - 過ぎた予定は薄く（実行ログに fired があれば「再生しました」、skipped/missed ならその旨）。
  - 無効な予定・全体オフ・禁止時間に当たる予定は破線＋理由を表示（禁止時間は月のアイコン、予告のピルは取り消し線）。
  - カードタップで編集シート。
- **データ**: 週カレンダー用の `GET /api/calendar?start=<その週の月曜>&days=8` をそのまま使う
  （発火判定は `scheduler.day_occurrences` = tick / `next_events` と同じ）。各予定には `past` / `enabled` / `quiet` / `tag` / `lead` が
  すでに付いているので、足したのは次の 2 つだけ:
  - 各予定の `result`: 過ぎた予定が実行ログでどうなったか（`fired` / `skipped` / `missed`、分からなければ `null`）。
    `scheduler.outcome()` がログの予定 id・名前・時刻と突き合わせる。
  - 応答の `master_enabled` と `quiet_hours`（全体オフの表示用）。
  - 0 時台の予定の予告は前日に鳴るので、画面側（`SL.eventsByDate`）で発火時刻の日付ごとに振り分け直し、
    予告には本番の時刻 `main_at` を付ける。そのために 7 日ではなく 8 日分を取る。

### 4. サウンド

- グループ「内蔵」「自分のファイル」「システム」。各行: 再生アイコンボタン＋名前。再生中の行はアクセント背景＋停止アイコン。
- 「自分のファイル」グループ末尾に「＋ ファイルを追加」行（隠した `<input type=file accept="audio/*" multiple>` を起動）。アップロード中は行内に進捗文言。
- 自分のファイルは「編集」または左スワイプで削除（確認は iOS 風アクションシート or `confirm()`）。
- 空の区分は「ありません」ではなく区分ごと非表示（システムサウンドが無い Linux などを考慮）。

### 5. 設定

- 最上部に「全体」グループ: **すべての予定を鳴らす**（全体オン/オフのスイッチ）、**いま鳴っている音を止める**（ボタン行）。
- 「既定」グループ: 音量スライダー、読み上げの声 ›、話す速さ。
- 「既定」グループの音量には試聴ボタン、話す速さの下に「声と速さを試聴」。
- 「禁止時間」グループ: スイッチ＋開始・終了（time 入力を行の右に）。説明文（「23:00 から 07:00 までに来た予定は鳴らしません（日付をまたぎます）。」など）はグループ下の footnote。
- 変更は**即時保存**（保存ボタン廃止、スライダーは離した時点で保存、成功時のトーストは控えめに）。
- 「記録」グループ: **実行ログ ›**（子画面でログ一覧。種類ごとの色バッジ、引っ張って更新 or 更新ボタン）。
- 「この Mac について」グループ（接続先・起動時刻・内蔵サウンド数・音声数・通信）。

## 挙動・その他

- `/api/now` のポーリング（10 秒）は継続し、次の予定バナー・タイムラインの現在線・再生中表示を更新。タブ非表示中（`visibilitychange`）は止める。
  「あと○分」と現在線は通信を待たずに 15 秒ごとに描き直す。
- 確認ダイアログ・トーストは iOS 風に（トーストは下タブバーの上に出す）。
- 既存の XSS 対策（`textContent` で描画）を維持。`innerHTML` にユーザ文字列を入れない。
- アクセシビリティ: スイッチは `role="switch"` + `aria-checked`、アイコンのみのボタンには `aria-label`、タブは `role="tablist"`。
- 現在の `renderDays()` 内の空ループ（`$$('#panel-schedules .quick button').forEach(() => {})`）は削除。

## 受け入れ条件

1. iPhone 相当（390×844、Playwright の iPhone 13 などのデバイス設定）で、4 タブ・編集シート・各子画面がはみ出し/重なりなく表示される（ライト・ダーク両方）。
2. 既存機能がすべて新 UI から操作できる（上の「既存機能は一つも落とさない」の一覧）。
3. `python3 -m unittest discover -s tests` が通り、`python3 tests/coverage_report.py` で `sounder/` の行カバレッジが 100%。
   `tests/test_web_lib.py` は `web/lib.js` の単体テストと、偽のサーバ応答で `web/app.js` を起動・編集シートを操作するテストを
   macOS の jsc（無ければ node）で走らせる。
4. Playwright でスクリーンショット（予定・編集シートと各子画面・タイムライン・サウンド・設定・合言葉の画面、iPhone SE / iPhone 13 × ライト/ダーク）を撮り、
   横スクロール・はみ出し・ページエラー・外部リクエストが無いこと、M PLUS Rounded 1c が効いていること、長い名前でも意味のまとまりの途中で改行しないことを確かめる。
5. README の Web UI に関する記述（「右上のスイッチ」など）を新しい配置に合わせて更新。
